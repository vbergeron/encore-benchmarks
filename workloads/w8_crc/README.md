# W8 — CRC-16 and CRC-32 in Gallina

Two checksums of the same block, the kind a firmware computes over every
frame it receives and every image it installs: CRC-16/MODBUS (serial
links) and CRC-32/ISO-HDLC (Ethernet, zip, most bootloaders). The plan
keeps W8 in the main results because it is the workload least favourable
to Encore: pure arithmetic in a tight loop, where an interpreter pays for
every instruction and R needs one table lookup per byte.

- **Program** (`theories/Crc.v`): `run n` returns the CRC-16 and the
  CRC-32 of the first `n` bytes of the input, the CRC-32 as its high and
  low 16-bit halves. Both use the bit-serial loop of a reflected CRC: XOR
  the byte into the low bits of the register, then eight times shift right
  and XOR the polynomial if a one fell out. The block is streamed through
  the input extern; no list is built.
- **Proved** (`theories/Crc.v`): both are the polynomial definition of
  the CRC. `crc_spec` reads the message as a polynomial over GF(2), each
  byte least significant bit first, and multiplies it by x^w. It adds the
  initial register to the w highest coefficients and takes the remainder
  of the schoolbook division by the generator polynomial (`poly_rem`, on
  lists of coefficients), then applies the final XOR. The generators are
  written as their exponents, `poly 16 [15; 2; 0]` and
  `poly 32 [26; 23; 22; 16; 12; 11; 10; 8; 7; 5; 4; 2; 1; 0]`.
  - `crc16_input_correct`, `crc32_input_correct`: for any input whose
    bytes are below 256, `crc16_input n` is the integer value of
    `crc_spec` for CRC-16/MODBUS, and `crc32_input n` its two halves for
    CRC-32/ISO-HDLC (`val_halves` gives `lo + 65536 · hi`);
  - on the way: `direct_spec`, the classic identity between the "direct"
    shift register that CRC code runs and division of the augmented
    message, and `direct_xor_in`, which justifies XORing a whole byte into
    the register before shifting;
  - `crc16_spec_check`, `crc32_spec_check`: the specification gives the
    check values of the CRC catalogue, 0x4B37 and 0xCBF43926 for
    "123456789".
- **N**: block size, 16, 64, 256, 1024 bytes of pseudo-random data
  (xorshift32, in `vectors/vectors.rs`).
- **Output**: the CRC-16, then the CRC-32's high and low halves, hashed in
  that order by every variant.
- **Trust**: `nat` as VM integers (`ExtrEncore.v`): every value stays
  below 2^16, which is why CRC-32 is split in two halves, Encore integers
  being 24-bit. `Nat.lxor`, `Nat.div2` and `Nat.odd` extracted to the VM's
  `int-xor`, `int-shr` and `int-and`. `input_byte` returns bytes (the
  theorems assume every byte read is below 256). The constants of `Crc.v`
  (reflected polynomials, `0xFFFF`, `0x8000`) extracted to literals in
  `Extract.v`. One extern, no argument beyond N.
- **Bitwise operations**: the plan chose W8 to test Encore's lack of
  bitwise operations. Encore has had them since then (`int-and`, `int-or`,
  `int-xor`, the shifts), and `ExtrEncore.v` maps `Nat.lxor` and friends to
  them, so W8 measures the VM with them. A variant without them (the
  Gallina `Nat.lxor`, which is a recursion over the bits) is not measured.
- **Heap**: 32 KiB by default, as the other workloads. The loop is
  tail-recursive and allocates only the CRC-32 pair of each byte, so the
  live heap does not grow with N: `cargo xtask minheap` passes at 512 B,
  its smallest step.

**Cost.** On the Cortex-M3, R executes 15 instructions per byte (two table
lookups). E executes about 1,040 VM instructions per byte, 65 per shift of
a register, and about 27.8k machine instructions: 27 per VM instruction,
as in the other workloads. With the optimizer off, E needs three to four
times more, and 1024 bytes overflow the 32 KiB heap, as in W0, W4 and W6.

**C** (CertiRocq): not built yet. The workload needs `Nat.lxor`,
`Nat.div2` and `Nat.odd` registered in `certirocq/theories/BenchNat.v`
(and realised in `bench_rt.c`), otherwise C would run them as recursive
Gallina, and its C generated by `certirocq/generate.sh w8_crc`.

The R variant is the usual table-driven CRC: two 256-entry tables built at
compile time in flash (1.5 KiB), one lookup per byte and per CRC.
